## Propósito, contexto y objetivos

Definir V3 como evolución condicionada a madurez, no reinvención de upstream.

## Alcance, arquitectura y decisiones

Posibles áreas: automatización empresarial avanzada, expansión de arquitecturas y ecosistema de extensiones. Mantener Debian como base salvo nueva decisión explícita documentada.

## Componentes y flujo operativo

1. Analizar adopción y deuda
2. identificar capacidad sostenible
3. ensayar
4. evaluar compatibilidad
5. decidir inversión.

## Seguridad y riesgos

No fijar porcentaje de código W4 como objetivo ni sustituir componentes maduros por identidad de marca. Capacidad de seguridad debe crecer con superficie.

## Criterios de aceptación

Aceptar visión con problemas concretos y condiciones de entrada, sin funciones afirmadas como existentes.

## Rendimiento y evidencia

Medir deuda y soporte.
