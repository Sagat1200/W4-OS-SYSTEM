# 396 · W4 OS — Upstream Contribution Policy

> **Edición documental:** 0.1 · **Fecha:** 2026-09-08 · **Idioma:** español  
> **Área:** Integración Debian · **Responsabilidad propuesta:** Mantenimiento upstream  
> **Estado:** especificación de diseño; implementación y calificación no acreditadas por esta entrega.

## Propósito, contexto y objetivos

Contribuir mejoras upstream para reducir divergencia y beneficiar mantenimiento.

## Alcance, arquitectura y decisiones

Política respeta guías del proyecto receptor y derechos de contribución; bugs se reproducen sin branding cuando sea posible. No exigir aceptación upstream para toda corrección urgente local.

## Componentes y flujo operativo

1. Preparar caso mínimo
2. revisar datos
3. enviar parche/reporte autorizado por proceso
4. seguir feedback
5. integrar versión aceptada
6. retirar delta.

## Seguridad y riesgos

No publicar vulnerabilidad sensible fuera del proceso coordinado ni enviar datos de clientes. Atribuir contribuciones y licencias correctamente.

## Criterios de aceptación

Aceptar contribución con seguimiento y condición de retirada del parche local.

## Rendimiento y evidencia

Medir deltas reintegrados y tiempo de revisión.
